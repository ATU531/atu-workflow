# Documentation after implementation

Use this reference only when verified implementation changed a documented fact.

Update affected statements in the existing operator, API, schema, configuration, architecture, or feature documentation. Keep durable repository-wide commands and conventions in the applicable AGENTS.md scope. Preserve unrelated user content; do not regenerate whole guides or add rule files merely to complete a workflow.

Ground claims in the current code/configuration and executed evidence. Plans, TODOs, mocks, and checked task boxes do not prove implementation or release. Distinguish implemented, tested, pushed, migrated, and deployed states; never describe an unexecuted deployment or migration as complete. Record uncertainty or leave the claim unchanged when evidence is missing.

Verify the affected links/paths, command definitions, API/model fields, configuration names/defaults, and changelog claims against their authoritative source. Configuration parity requires a comparison with the relevant schema/sample; use sanitized examples without live secrets. State which checks ran and which remain unavailable in the selected workflow's existing handoff, without adding another report or evidence ledger.
